# Проверка всех Android unit-тестов

Задача записана по просьбе пользователя 18 ноября 2026 года. Аудит и полный
прогон завершены; описание инфраструктуры — в [TESTING.md](TESTING.md).

## Выполненная работа

1. Прочитать AGENTS.md и проверить рабочее дерево, сохранив чужие изменения.
2. Запустить unit-тесты всех модулей и нужных build variants через Gradle (`test`),
   собрать список конкретных ошибок компиляции и падений assertions.
3. Для каждого падения определить причину: устаревший контракт теста, неправильная
   фикстура или реальный дефект приложения. Не ослаблять assertions ради зелёной сборки.
4. Исправить на владеющем слое и перепроверить сначала конкретный модуль, затем
   весь набор unit-тестов. Отдельно указать пропущенные проверки и внешние зависимости.

## Проверенный объём

Полный `test` прошёл: 220 уникальных сценариев, 466 запусков по debug/release и
dev/prod, без падений и пропусков. Собран `:app:assembleDevDebug`.
Отдельно прошли 2 теста Gradle artifact transform.

Все 20 наборов presentation-тестов, использующих Orbit helper (10 модулей ×
debug/release), выполнены с coverage-agent JetBrains при намеренно отображённом
в память legacy `testing.jar`. Получены непустые `.ic`-отчёты в
`build/diagnostics/coverage/`. Mutable JAR исключён из classpath потребителей;
используется `testSupportClasses` и content-addressed transform cache.

Это не Android instrumentation/UI/FCM/WebSocket end-to-end проверка и не
утверждение о 100% покрытии ветвей. В Android Studio после изменения build scripts
нужен Gradle Sync; покрытие через кнопку IDE отдельно не запускалось.
